# Агенты системы

## Общая архитектура

Взаимодействие агентов в основном **линейное**:  
`Main Agent` → `User Profile Agent` → `Vacancy Agent` → `Main Agent`

Однако возможны сценарии без `User Profile Agent` или `Vacancy Agent` (например, простой чат или запрос, не требующий анализа резюме/вакансий).

**Важно:** Общение с пользователем ведёт только `Main Agent`. Остальные агенты работают внутри графа и не имеют прямого контакта с пользователем.

## 1. Main Agent

**Файл:** `agents/main_agent.py`

Главный агент-оркестратор. Задачи:
- Маршрутизация запроса к нужному агенту
- Обработка ответов
- Контроль безопасности (через `security_node`)
- Отслеживание отклонений от целевых сценариев

### Ноды Main Agent

| Нода | Тип | Назначение |
|------|-----|------------|
| `security_node` | conditional node | Проверяет входные сообщения на **out-of-scope**, инъекции, jailbreak. При обнаружении угрозы направляет в сценарий `chat` / `security`. |
| `main_node` | основная нода | Запускает один из пяти сценариев на основе анализа запроса пользователя. |

### Сценарии main_node

| № | Сценарий | Условие активации |
|---|----------|-------------------|
| 1 | `recommend_vacancies` | Пользователь прислал ссылку на резюме **и** просит найти работу/вакансии. |
| 2 | `career_track` | Пользователь прислал ссылку на резюме **и** просит построить план развития / карьерный трек. |
| 3 | `parse_resume` | Пользователь **явно** просит проанализировать, разобрать или оценить его резюме/опыт (наличие ссылки обязательно). |
| 4 | `market_analysis` | Вопросы о зарплатах, популярных технологиях, ситуации на рынке («что сейчас ищут»). Если есть ссылка на резюме, но нет явной команды на анализ — сценарий выбирается на основе запроса (вакансии или трек). |
| 5 | `chat` / `security` | Активируется, если: <br> - `security_node` обнаружил угрозу; <br> - запрос не соответствует ни одному из вышеперечисленных сценариев (агент пытается направить пользователя к одному из них). |

## 2. User Profile Agent

**Файл:** `agents/user_profile_agent.py`

Специализируется на **анализе профиля пользователя** и его **адаптации** под формат, необходимый для RAG и поиска вакансий.

### Функции и ноды

| Компонент | Тип | Назначение |
|-----------|-----|------------|
| `format_to_candidate_profile` | вспомогательная функция | Преобразует поля из `UserProfile` (резюме пользователя) в формат `CandidateProfile` (формат вакансии), используя опыт пользователя. Это улучшает векторизацию при поиске. |
| `user_profile_node` | нода графа | Обрабатывает сценарии, связанные с резюме: парсинг, анализ, вызов LLM для выделения ключевых навыков и опыта. |

## 3. Vacancy Agent

**Файл:** `agents/vacancy_agent.py`

Специализируется на **вакансиях** и **карьерных треках**. Имеет встроенное знание о рынке труда по специализации пользователя. Может рекомендовать вакансии и строить карьерные траектории.

### Инструменты (tools)

| Инструмент | Назначение |
|------------|------------|
| `read_vacancies_by_title` | Загружает из базы данных вакансии, соответствующие специализации пользователя (по заголовку/ключевым словам). |
| `generate_final_recommendations` | Генерирует **карьерный трек** на основе трёх входных данных: <br> - `profile` – резюме пользователя; <br> - `current_recs` – рекомендации от `Recommender` (RAG-поиск); <br> - `market_response` – анализ рынка труда от LLM-агента. |

### Нода Vacancy Agent

| Нода | Назначение |
|------|------------|
| `vacancy_node` | Обрабатывает сценарии, требующие понимания рынка труда или работы с вакансиями (поиск, подбор, построение треков). |
