# Governance & Risk Management

## 1. Risk Register

| Риск | Вероятность / Влияние | Детект | Защита (Mitigation) | Остаточный риск |
| :--- | :--- | :--- | :--- | :--- |
| **Prompt Injection** | Высокая / Высокое | Security Node (LLM-Judge) | Семантический фильтр на входе, изоляция системного промпта | Средний |
| **Галлюцинации** | Средняя / Среднее | LLM-Judge (Fact checking) | Grounding на базе реальных вакансий (RAG) | Средний |
| **Утечка PII** | Низкая / Высокое | Логирование | Анонимизация данных перед отправкой в LLM | Низкий |
| **Блокировка API** | Средняя / Высокое | Мониторинг кодов 429/500 | Fallback на локальные модели (Llama 3) | Низкий |
| **Деградирование данных** | Средняя / Высокое | проверка llm-judge сценария recomnd_vacacies | Хорошая фильтрация данных | Высокое |

## 2. Политика работы с данными
* **Персональные данные:** Система не сохраняет историю диалогов. Персональной информация пользователя не используется и не хранится.
* **Логирование:** Хранятся только логи работы агентов и метаданные (время, затраты токенов). 
* **Retention:** Логи сессий не сохраняются.

## 3. Защита и безопасность
* **Injection Guard:** Каждый входящий промпт проходит через `Security Node` перед попаданием в `Main Agent`.
* **Human-in-the-loop (HITL):** Множество FallBack в END, при наличии проблем и отдельный сценарий для обработки этого.
